## 🔧 Reliability release — interactive login & token refresh

This release fixes two reliability issues in the authentication layer. **If you
use the default stdio transport with `service` auth, nothing changes in how the
server behaves — but you still benefit from the no-hang fix below.** The
behaviour changes affect the interactive `web`, `public` and `installed` login
flows and the token-refresh path.

### What was wrong
- **Browser login could hang forever and block the server (issue #14).** After a
  single callback timeout the listener thread kept running and held the redirect
  port, so the next login hit "address already in use" and the server waited on
  it indefinitely. While waiting for the browser callback the login also blocked
  the asyncio event loop, so the server stopped answering other requests, and a
  callback that arrived after the timeout told the user "Authorization
  successful!" even though the code was discarded. The `installed` PIN prompt
  additionally read the process stdin, which on the stdio transport is the MCP
  protocol stream.
- **Concurrent token refreshes raced (issue #15).** Several tool calls arriving
  at once could each see the token as expired and each run a refresh with the
  same refresh token. With refresh-token rotation only the first succeeded and
  the rest fell through to an interactive login.

### What changed
- The callback listener is now torn down on every exit path and the redirect
  port is released, so a timed-out login can be retried.
- A port-bind failure now surfaces as a clean `AuthError` instead of hanging.
- Waiting for the browser callback no longer blocks the event loop.
- A late callback is no longer reported to the user as a success.
- The `installed` flow refuses to prompt for a PIN when stdin is not an
  interactive terminal, so it can no longer corrupt the stdio protocol stream.
- Token refresh/acquire is now serialised, so concurrent tool calls trigger
  exactly one refresh and the rest reuse the result.

### Upgrading
No configuration changes are required. `pip install --upgrade accelo-mcp` (or
your usual installer) is enough.

## What's Changed
* fix(auth): clean up the OAuth callback listener, free the port, stop blocking
  the event loop, and guard the `installed` PIN prompt against a non-TTY stdin
  (issue #14)
* fix(auth): serialise token refresh/acquire behind a per-instance lock with a
  re-check so concurrent calls trigger exactly one refresh, and only drop a
  refresh token when it is provably dead (issue #15)
